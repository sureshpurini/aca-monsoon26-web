    Functional unit status

    Who produces my operands — and am I still going to read them?

    reading Q and R as a pair: Q=unit  R=N waiting for that unit Q=—  R=Y ready, not yet read Q=—  R=N already read

    R = N covers two opposite situations — Q tells them apart. A writer is blocked exactly while some other unit still shows R = Y on the register it wants.

    Register result status

    Which unit is going to write each register. Blank means nobody. Address registers (x1, x2, x3) are tracked like any other source — nothing in these programs writes one, so they stay blank and never block a read.

    Keyboard: ← → step, Space play/pause, Home / End jump, 1 2 switch example.

    Issue is in program order, one instruction per cycle. Nothing is forwarded: a consumer waits for its producer to reach the register file. All four checks are evaluated against the state at the start of each cycle, which is why a value written in cycle n is not readable until n+1.
